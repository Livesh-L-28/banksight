# Assumptions and Dependencies
## Project Name: BankSight — Banking Customer Intelligence & Retention Platform
**Document Version:** 1.0.0  
**Date:** 2026-11-07  

---

## 1. Project Assumptions

1. **Synthetic Data Realism:**
   - The synthetic dataset generated by `scripts/generate_synthetic_data.py` accurately mirrors real retail banking portfolio distributions (age brackets, income deciles, account type splits, balance decay, and transaction seasonality).
2. **Predictive Lead Time:**
   - A 60 to 90-day observation window prior to defection provides sufficient signal in transaction velocity and balance trends for machine learning models to detect attrition patterns.
3. **Operational Human Intervention:**
   - Relationship managers have operational capacity to review and engage with at least 15-20 high-risk customer cases per week.
4. **Attribution Modeling Standard:**
   - Campaign revenue attribution utilizes a last-touch or time-decay model within a 30-day conversion window following customer campaign exposure.
5. **Currency Consistency:**
   - All balance, transaction, and income figures are denominated consistently in USD (\$) across the platform.

---

## 2. System & Environment Dependencies

1. **Runtime Environment:**
   - Python 3.12+ 64-bit environment with modern packages (Pandas, NumPy, Scikit-learn, SQLAlchemy, Streamlit, Plotly, ReportLab).
2. **Database Engine:**
   - Production / Docker environment: PostgreSQL 16+ with standard relational constraints and connection pooling.
   - Development / Smoke-test environment: SQLite 3.35+ (built into Python) with full foreign key constraint enforcement enabled.
3. **Container Infrastructure:**
   - Docker and Docker Compose v2 for multi-container deployment (PostgreSQL db service + BankSight Streamlit app service).
4. **CI/CD Platform:**
   - GitHub Actions runner with Python 3.12 and PostgreSQL service container for automated regression testing and linting.
